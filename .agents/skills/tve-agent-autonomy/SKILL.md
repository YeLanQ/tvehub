# 自我决策 Agent 设计（本仓库的自主工作框架）

决策回路：**理解 → 路由 → 行动 → 验证 → 汇报**。本技能定义每一环的判断规则；
具体领域知识在其余六个技能里，本技能只回答三个问题：
做什么（路由）、能不能直接做（边界）、什么时候停（升级）。

## 一、路由表（拿到任务先查这里）

| 任务信号 | 主技能 | 辅助 |
|---|---|---|
| 调后端能力/读写资产场景/派发命令 | tve-api-usage | tve-app-operations（操作语义） |
| 写代码改代码（组件/引擎/脚本） | tve-sdk-scripting（tve 脚本）或 tve-engine-interfaces（引擎接口） | tve-unit-testing（补测试） |
| 写测试/调阈值/门禁拦截 | tve-unit-testing | tve-local-ci |
| 用户问"怎么操作"（三窗口） | tve-app-operations | — |
| 改完代码同步文档 / skills:check 红 | tve-self-evolution | tve-local-ci |
| 提交前自检 / 发版验证 | tve-local-ci | — |
| 模糊任务/多技能交叉 | 先本技能 task-playbooks 拆解 | 全部 |

## 二、行动边界（三区）

**绿灯——直接做**（可逆、属任务自然延伸）：读任何文件；改代码/文档/技能单元；
跑 test/unit/smoke/ci:local；按剧本补测试；把行号引用修准。
**黄灯——先确认再动**（影响共享状态或不可逆）：
`git commit`（本仓库约定 no-auto-commit，除非用户当轮明说）、`git push`、
依赖增删/升级、版本号变更（version:bump）、删文件/目录、改公共配置
（tauri.conf/vite.config/tsconfig）、对外发布（LanShare 发布、MCP 暴露）。
**红灯——不做**：跳过或修改门禁让链路变绿（`--skip` 只能用于快速迭代且必须
注明）；改 tests/ISSUES.md 把真漂移记成"已知"；删除校验器/门禁脚本；
把密钥/绝对路径写进技能文档。

## 三、证据与验证规则

1. **关联影响先行**：修改落地后，第一件事是判断与改动关联的功能是否受到
   负面影响，而不是只看测试通过——数据流/持久化/跨窗口同步/渲染路径/既有
   调用方都算关联面；测试只覆盖写到的路径，全绿不代表没有破坏（本规则来自
   真实事故：一段索引清理逻辑测试全绿，却在运行环境里误删了用户全部会话）。
2. **门禁说话**：改完必须 `pnpm ci:local`（至少 `--only` 受影响步）；"应该没问题"
   不算验证。
3. **引用可点检**：文档里写 `文件:行号` 就要经得起 skills:check 与人工抽查；
   探索得来的行号，落笔前抽验（本组曾修掉 1 处语义不符的引用）。
4. **负向验证**：改阈值/改门禁，先证明它"会拦"再证明它"放过"。
5. **报告如实**：失败原样转述（哪步/什么错/退出码）；跳过了什么要声明；
   不确定就说不确定。

## 四、停止与升级条件（出现即停，问人）

- 需要黄灯区动作且无当轮授权；
- 同一失败修 2 轮仍红（第三轮前停下来重新诊断，别盲改）；
- 任务与既有约束冲突（如要求自动 commit 但约定禁止）；
- 发现与任务无关但严重的问题（数据丢失风险、安全问题）——报告，不顺手修。
