# 单元：任务剧本（四类高频任务的标准流程）

## 剧本 1：修 bug（用户报了个错误行为）

1. **复现优先**：找到能观察错误的最近入口——组件单测（tve-unit-testing 找模式）、
   framework 纯逻辑 spec、smoke 单套件（`pnpm smoke <id>`）。
2. 定位：`tve-api-usage` / `tve-engine-interfaces` 找契约（行为应为哪条），
   读实现找偏差；引用 `文件:行号` 记录根因。
3. 最小修复 + **先补失败用例再修**（红 → 绿是修复正确性的证据）。
4. 验证：`pnpm vitest run <file>` → `pnpm ci:local`。
5. 若根因是契约本身变了（不是 bug 是漂移）→ 转剧本 3。

## 剧本 2：加功能 / 加 API

1. 路由到领域技能确定接入点（新命令 → commands-registry；新节点类型 →
   prototype-model 必做清单；新资产类型 → assetService 模式）。
2. 按单元三段式实现：代码 + 真实调用点 + 测试（四类输入）。
3. 同批走 `tve-self-evolution` drift-map 同步技能文档（同一次改动里完成）。
4. 验证：`pnpm ci:local`；涉及 src/runtime → 确认 build-runtime 产物再生。
5. 收尾汇报：做了什么/链路结果/哪些是跳过或待办（如有）。

## 剧本 3：文档漂移同步（skills:check 红，或改码后主动同步）

1. 读 drift-map.md 找"改了什么 → 动哪些单元"。
2. 逐单元更新；行号引用重新定位（定位不到就降级为不带行号的路径引用）。
3. `pnpm skills:check` 归零（允许的告警只剩"推荐补测的示范 spec"）。
4. 若是**用户报了操作行为与文档不符**：先核实代码现状（行为对不对），
   行为错转剧本 1，行为对才改文档——不要反过来照着错的行为改文档。

## 剧本 4：只验证（用户只要确认现状健康）

1. `pnpm ci:local`（时间紧用 `--only skills,unit` 但要声明不完整）。
2. 需要留档/趋势 → `--full`（写 reports/<日期>/）。
3. 汇报格式：各步 ✔/✗ + 耗时 + 失败的根因定位（引用 `文件:行号`）+
   已知漂移项（对照 tests/ISSUES.md）单列，不与真失败混淆。

## 通用收尾（所有剧本）

- 报告首句给结论（修好了/没修好/链路绿没绿）；
- 列出改动文件与关键证据；
- 声明未覆盖项（Rust 侧、真机 Tauri 分支、P1 已知漂移）；
- 不主动 commit（黄灯）——除非用户当轮明说。
